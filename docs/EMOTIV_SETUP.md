# Emotiv EPOC X и проведение теста

## Термины

- **Cortex API** — программный интерфейс Emotiv.
- **Performance Metrics** — рассчитанные Emotiv показатели, доступность и состав которых зависят от версии, лицензии и устройства.
- **виртуальное устройство** — источник тестовых данных Launcher; его значения не следует описывать как клинические измерения.
- **профиль** — настройки/данные пользователя или функций Emotiv, а не готовый профиль усталости.

## Подготовка и запуск

Перед показом запустите Emotiv Launcher и виртуальный EPOC X. Затем запустите
`start-live.cmd` из корня проекта через обычную Командную строку. Backend
авторизуется в Cortex, подключается к EPOC X и подписывается на `met`.

## Фактическая проверка 2026-11-05

Прямой read-only запрос к локальному Cortex API выполнен без экспорта записи и без Client Secret:

- WebSocket endpoint: `wss://localhost:6868`;
- Cortex: `4.13.5.3`;
- найден виртуальный `My EPOC X`, id `EPOCX-3C0EF39F`, статус `connected`;
- `isVirtual: true`, подключение через dongle;
- EPOC X сообщает `eegRate: 128`, `memsRate: 32`;
- второй найденный виртуальный Insight имеет статус `discovered`.

Подтверждённый Live-поток проверен далее; ненужные диагностические пробы в
обычном запуске больше не используются.

## Фактический Live-контракт EPOC X

Проверка 2026-11-05 успешно создала сессию EPOC X и подписалась на `met`, `mot`, `dev`.

Для `met` Cortex вернул следующие колонки:

```text
attention.isActive, attention,
eng.isActive, eng,
exc.isActive, exc,
lex,
str.isActive, str,
rel.isActive, rel,
int.isActive, int
```

В 10-секундной проверке получено 342 сообщения. Пример фактического `met`-массива:

```json
[true, 0.5, true, 0.5, true, 0.5, 0.0, true, 0.5, true, 0.5, true, 0.5]
```

Нормализатор `backend/cortex_metrics.py` использует только эти подтверждённые колонки. Названия `eng`, `exc`, `lex`, `str`, `rel`, `int` сохраняются как поля Emotiv и не переименовываются в медицинские показатели.

## Профили и Mental Commands

Для этой курсовой не требуется обучение Mental Commands и управление объектами силой мысли. Профиль не равен профилю усталости. Нужны только разрешённая авторизация, сессия устройства и фактически доступный поток метрик.

## Перед тестом

1. Запустить Launcher.
2. Запустить Live-сервер командным файлом `start-live.cmd`.
3. Дождаться в окне CMD строк `Live Cortex subscribed` и `service_status: ready`.
4. Запустить Unity.
5. Нажать «Начать тест».
6. Выполнять задания до автоматического завершения через 60 секунд.
7. Дождаться экрана результата и сохранить идентификатор сессии.

## Контроль качества сессии

Сессия пригодна для анализа, если:

- есть `session_start` и `session_finish`;
- длительность находится в ожидаемом диапазоне;
- есть поведенческие события;
- есть gaze-события;
- есть источник `live`;
- нет пропуска времени, который превышает допустимый порог.

## На защите

На защите используется Live-сценарий. Метрики Emotiv получены от виртуального EPOC X, а окулографические события моделируются в Unity.

## Локальная конфигурация

Для учебного проекта значения Cortex-приложения находятся в `backend/live_config.py`, поэтому перед показом не требуется вводить переменные окружения.
