# Архитектура приложения

## Общая схема

```text
Emotiv Launcher / EPOC X
          |
          | Cortex API: фактически доступные met-показатели
          v
Python Neuro Service <---- WebSocket ----> Unity Operator Test
          ^                                      |
          |                                      |
  aggregation/model                    behavior + simulated gaze
          |
          v
  fatigue_score and class ---------------> Unity result UI
```

## Компоненты

### Unity Operator Test

Отвечает за стартовое окно, сцену, состояние теста, задания, ввод пользователя, raycast-взгляд, поведенческие события, состояние обмена и экран результата. Unity не вычисляет итоговый показатель усталости, но отображает полученный от backend результат.

Минимальные состояния теста:

```text
StartScreen -> Connecting -> Ready -> Running -> Analyzing -> Result
```

При ошибке соединения Unity показывает понятное состояние и позволяет повторить подключение.

### Gaze Simulator

Каждый кадр или с фиксированной частотой выпускает положение виртуального взгляда, объект под лучом и события фиксации. Raycast должен исходить из камеры и попадать в размеченные цели. Случайный шум добавляется поверх сценария, связанного с целями.

### Python Neuro Service

Содержит простые части обработки:

- `CortexAdapter` — подписка на фактически доступные метрики Emotiv;
- `SessionAggregator` — окна и сводные признаки;
- `FatigueScorer` — пороговый индекс первой версии;
- `WebSocketServer` — обмен с Unity.

### Scoring

Сначала нормализуются признаки, затем вычисляются компоненты:

```text
behavior_component = reaction_time + errors + missed_targets
gaze_component     = fixation + dispersion + distractions
emotiv_component   = фактически доступные метрики Emotiv
fatigue_score      = weighted sum of components, clamped to [0, 1]
```

Весы и направление влияния должны быть вынесены в конфигурацию и описаны как эвристика прототипа. На первом этапе не использовать слово «обученная модель», если обучение на размеченном наборе не проведено.

## Backend boundary

Python отвечает за подключение к Cortex API, приём и агрегацию данных, расчёт признаков и индекса, диагностический лог и выдачу результата.

Unity отвечает за весь пользовательский поток, отрисовку стартового и итогового экранов, запуск и остановку теста, показ прогресса и состояния соединения.

## Транспорт

WebSocket работает локально на `127.0.0.1`. Сообщения — UTF-8 JSON с полем `type`, версией схемы `schema` и идентификатором сессии. Подробный контракт находится в `DATA_CONTRACT.md`.

## Ошибки и восстановление

- Unity может запуститься до Python: клиент повторяет подключение.
- Python сообщает об ошибке подключения к Cortex, а Unity показывает состояние соединения.
- Неизвестные поля Emotiv не должны ломать обработку базовых признаков.
- Завершение сессии идемпотентно по `session_id`.
